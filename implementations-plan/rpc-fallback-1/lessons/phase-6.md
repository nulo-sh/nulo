# Phase 6 (arc 3): the background routes

The owner answered OA-1 (B), OA-8 (A) and OA-2 (the proposed text) on 2026-11-05, before this phase started, so its two steps ran in order.

- `NetworkService.nodes` (keyed by chain) became `routes` (keyed by network row, with the endpoint list each was built for). `getNodeFor(network)` rebuilds when a caller's row lists other endpoints than the cached route; every endpoint mutation, `setActiveNetwork`, `deleteNetwork`, a retirement and a reset evict the row's route; a rename keeps it. `setActiveNetwork` and the seeding no longer pre-build a node: the route is built at the first read, which is where a refused URL now fails.
- Moved onto the route: `getNode(chainId)`, `readChainTip` and `readPublicStorageOnce` (both through `getSingleAttemptNodeFor` with their own budgets), the view executor's two node reads, the auth registry's registry reads, the incoming-transfer receipt fee. The auth registry's receipt reads stay on the pinned client of the primary until Phase 7 moves them to each transaction's recorded endpoint.
- Status (OA-1 B): `getNodeStatus` reads `getNodeInfo` through the route and is `InvalidChain` only when every endpoint that answered is `wrong-chain`; `probeNodeStatus` probes the route's active endpoint first, then the rest in preference order, under one shared budget, asking nothing else while the first answers. Backup export and the senders restore follow the same two methods unchanged. A chain-0 row whose every endpoint is remote has no route (the router keeps only loopback endpoints on chain 0), so `getNodeStatus` reads `Inactive` there where it read `InvalidChain`; the header shows both as "Cannot reach the network", and the probe still reads `InvalidChain`.
- **Found by the wiring (D31):** `route.singleAttempt` failed at once on a route with no active endpoint. A multi-endpoint route starts with none until admission, and the background builds its routes afresh after every worker restart, so the first bounded read after each restart (the send's tip gate, the sponsor and fee-juice funding probes) would have failed. `singleAttempt` now runs admission first, no probe starting past the caller's deadline, and makes its one attempt with what the budget has left.
- `_getChainId` lost its last caller and went; its tests call `_probeChainIdentity`.
- The type-roles inventory pins `auth-registry/service.ts`'s digest as an `action_operations` producer file: re-attested (the producer hits and the evidence text are unchanged; only node accessors moved) and re-pinned.
