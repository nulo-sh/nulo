# og-cards-1: phase 1 (the card, its check, the renders)

- 2026-11-10: `bun install` after adding `puppeteer` `^25.14.0` to the landing changed one `bun.lock` line (the landing's `devDependencies`), no package; the non-frozen install passed the age gate, then `bun install --frozen-lockfile --force` reinstalled 999 packages, exit 0.
- First render refused the index title: `scrollHeight` 96 in a 86 px box at 84 px with `line-height: 1`. Space Grotesk's ascent plus descent is about 1.26 em, so a tight line box always reports overflow; raising the line height only moved it (102 in 97). Switched to a declared line budget per box (D11): lines = height ÷ line-height, plus width and the safe rectangle, with no clipping.
- Proofs, each restored afterwards: a changed `1.2.0.toml` title reds `og-card.test.ts` with "is stale against its inputs: run bun run --cwd apps/landing og:cards"; a rerun of `og:cards` writes nothing (`3 card(s), 0 rendered`, checksums equal); a 59-character title is refused ("takes 3 lines, at most 2"); an unbroken word is refused ("is 692px wider than its column"); a `url(https://example.invalid/x.png)` rule is refused ("the card asked for ...").
- A first try of that last proof put the `url()` before the rule's own `background` shorthand, which reset it, so no request happened and the run re-rendered all three cards from the scratch template; restoring the template and re-running re-rendered them from the real one. Lesson: a negative proof needs a positive control that the bad input really reached the system.
