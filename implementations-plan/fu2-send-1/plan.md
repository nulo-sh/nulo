- **One source for sends in progress** (#1521, #1522, arc 3, after OA-2 and OA-3): new C1 composable `composables/useSendsInProgress.ts`, built once in `popup/app.vue` beside `useArrivals` and provided by an injection key as it is. It owns the shell's journal mirror (`useJournalMirror`, its own `OperationJournalServiceClient`, connected and disconnected by app.vue) over the active scope; a lock or a scope change empties it. It exposes the in-scope in-flight records (`isInFlightActivityOp`, a new predicate in `utils/journal-state.ts` that Home's filter also calls), newest first. The toast and History read this one list, so they cannot disagree; Home keeps its own mirror, which also carries terminal records and task decoration. It never runs in a dApp window (an explicit route gate: `useArrivals`' scope does not exclude those routes).
- **P93-08** (#1521, arc 3): the composable shows one `{ kind: "info", label: "Sending <amount> <symbol> to <0x0c2b…4b5c>" }` toast for the newest in-flight `transfer` the person has not dismissed (OA-2 3A), and closes it when no such send is left, only if the toast showing is its own. Another message replacing it is not a dismissal: when the toast goes empty and the send still runs, it opens again (1A). The toast going empty while its own was showing, with nothing else opened, is the ×: every send running then counts as dismissed until a lock or a scope change clears the set (2A; D13). On a lock or a scope change it closes its own toast first, then drops its state; after an unlock a send still running shows again, as at popup open. The symbol and decimals come from app.vue's token lookup (`arrivalsTokens`); the lookup is fenced by the epoch and the record's state, so a record that ends or a scope that moves during it announces nothing. A token the lookup cannot read gives "Sending to 0x0c2b…4b5c" (OA-3 2A). The summary is the one `send-submit.ts` builds for "Transaction submitted", moved into `utils/` and shared; the amount is parsed with `parseSide` before it is formatted, and the address checked with `isValidAztecAddress`. Send's submit path does not change: its success or failure toast replaces this one.
- **P93-09** (#1522, arc 3): History lists the injected records first (transfers and dApp operations, OA-3 1A), filtered by `?token=` like every row, as `TransactionAwaitingCard`s (the layout its settled rows share) with Home's title, icon and chip helpers, the stage line `Pending · <progress word>`, and no action. The progress word is Home's own: the journal-only part of `awaitingSubtitleFor` (a queued send reads "Waiting for your earlier send", proving names its backend) moves into the shared util, so History and Home read the same word. The empty state (`activity.vue:220-224`) counts the pending rows. Its terminal mirror stays as it is. `filterPendingDoubleRender` moves from Home's feature folder into `utils/` (its element type kept) so History hides a pending chain row that a `submitting` record names. Home's amount and symbol helpers move into a shared util with the same `parseSide` guard.
- **Arc 3 amendment, approved 2026-11-02 (A4, D10)**: `useJournalMirror` lets a snapshot that began before an event and lands after it overwrite that event (`useJournalMirror.ts:55`, pinned by `useJournalMirror.test.ts:63`). Codex final reproduced a terminal update undone by such a snapshot, which would leave a ghost pending row and a Sending toast up after the send ended; the worker's `getOperations` decodes after reading raw rows, so a transition can commit between the two (production timing plausible but unverified). Fix in the mirror: record the events that arrive while a snapshot is out and replay them over it when it lands. It adds transient state and an ordering contract (a superseded or failed snapshot drops its record; a delete replays as a delete; a scope change and `dispose()` clear it). Home's and History's terminal mirrors gain it too; the pinned test changes meaning.
- **Not taken**: a toast opened from Send's submit (it misses a send in flight at popup open, and is a second source); moving Home onto the shell's list (its mirror holds terminal records and decoration; a refactor no pick asks for); polling or a second mirror for the snapshot race (more obligations than the replay); a roving tablist for the priority row (D4). `utils/in-flight-send.ts` is not the predicate: it guards scope switches for popup sends by stage and is not the activity set.

## Security & Adversarial Considerations

- **Privacy**: a public origin names the sender on chain. P93-01 starts a send on Public only when the private side is empty, where a private send cannot run at all; From, the privacy strip and the review still show the side. The panel recommended C for this reason; the owner signed B.
- **Hostile data**: balance strings and journal records come from storage. `parseSide` refuses a malformed side (Send reads private). Arc 3 parses `amountRaw` before `balanceFormatted`, which would throw on a non-integer string (Codex R1: demonstrated at the formatter; a journal row carrying one needs a writer the wallet does not have, as the journal is sealed and outside backups), and checks the recipient before it builds the toast.
- **Scope**: the shell's list holds only the active scope; a lock or a switch closes the toast it owns before its state goes, so another profile's amount and recipient never stay on screen. **Logging**: no new log line. Crypto, permissions, supply chain: no change.
