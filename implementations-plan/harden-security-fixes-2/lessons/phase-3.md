# Phase 3: the re-read and the trust

- `TokenService.refreshRestoredTokens(fence, deadlineAt)`: asserts the run fence, then reads every row of the fence's profile in parallel. Each read picks the row chain's first network (`getNetworksRaw`) and first account (`getAccounts(…, true)`), runs `previewTokenMetadata` with no class pin, and is raced at the remainder to the deadline (`settleBy`). The write happens under the token lock and only when the row is still the same token (profile, chain, contract), differs from the chain, its chain is live, the lock is still owned, the deadline has not passed and the fence is live. `clearChainState` takes no token lock, so a write re-checks the chain afterwards and deletes its own row if the sweep landed first.
- `onTokenUpdated` (`TokenInfo & { profileId }`) fires once per changed row. Send (`onTokensChanged`), `useScopedTokens` and the token settings re-read on it; `incoming-transfer` does not subscribe. `token-balance` was first left out too, which kept the backup's metadata on every balance until the next activation: its map of tokens is loaded when the profile activates, before the re-read (D22).
- One deadline for the tail: `useFullBackupImport` takes `tailDeadlineAt` before the account-state stage, `runImportChainSync` takes it as `deps.deadlineAt`, and `refreshRestoredTokensStage` races the RPC at the same remainder and closes its port. `useRestoreAgain` and the retry path pass a fresh deadline of the same budget. The re-read never fails the import.
- `trustRestoredTokens` is gone with its stage, method, spec line and client entry. A restored token's first note is `pending` and prompts once; the update event trusts nothing; an added token's note stays visible (the existing add-trust test is the control).
- Break-it checks: deleting the deadline check under the lock, or the same-token check, turns its test red ("reaches the lock after the deadline", "an id taken by another token during the read").
- Test placement: the plan named `send-amount.test.ts` for the open Send page; that helper takes the decimals as an argument, so the test that proves the re-read is in `send.test.ts`, which mounts the page (an update after mount sends `1.5` with 4 decimals as `15_000n`).
