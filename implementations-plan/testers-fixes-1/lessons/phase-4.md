# Phase 4: routes keep and reset scroll (#582)

- Verified D2's ordering against vue-router 5.2.0's `dist/vue-router.js`: `finalizeNavigation` pushes the history entry, sets `currentRoute`, calls `handleScroll` (which waits `nextTick()` before `scrollBehavior`), and `triggerAfterEach` runs right after it, before the render flush; the pop path (`setupListeners`) runs the same two in the same order. web history's `position` is `+1` on a push, kept on a replace, the entry's own on a pop. A duplicate navigation calls `handleScroll(from, from, true, false)` with a failure, so `afterEach` skips `leave` and `arrive` sees an unchanged position: nothing moves.
- `popup/scroll-memory.ts` as D2. `pageScroller` returns the page root when it scrolls, else the first scrolling descendant (a `TreeWalker` in document order), else null; a non-element root (fragment, comment) is null.
- The memory starts with no shown position, so the first navigation writes nothing and a reloaded first navigation (non-null `saved`) restores nothing.
- Unit test (`scroll-memory.test.ts`, 10 cases) replays each navigation in the router's order: `leave` then `arrive`. After the Opus review, a page that leaves its entry with no scroller clears that entry (`leave(null)`), so a replaced page's offset never reaches the next page shown there.
