# Phase A3: the choices

## Deviations from the plan (the tree wins)

- **Service.** `importMnemonic`, `restore` and `finalizeRestore` take a passkey answer beside the password; the new row is sealed under whichever is given, and a passkey seal takes an input no stored row opens under. `changeUnlockMethod(id, current, next)` refuses a password to a password (that is `changeProfilePassword`) and allows a passkey to a new passkey. Its reseal is proved before the write: the replacement must open under its new unlock to the same master, entropy and DEK. A rejected write is read back: the original there rethrows, the replacement there is a change made, anything else is reported as a change. `verifyProfilePassword` is new: the password profile's Continue checks the password before any passkey is made, so a wrong one shows "Wrong password" with no passkey left behind. `UnlockMethodChangedError` (registered in `packages/extension-messaging/src/errors.ts`) is the one typed error the page branches on.
- **Bearer.** `SessionManager.open` lost its passhash presence argument: every open with a DEK persists a bearer unless strict mode is on, whatever the profile's unlock. The silent restore skips a row no unlock opens (retired or unreadable), where it used to skip every passkey row.
- **Ceremony.** `PasskeyStep` gains `import`, `restore`, `accountFile` and `unlockMethod`. "Use a passkey I already have" is a `discover` request: a get naming no credential at the new profile's own fresh input, on the page (PATH A) and in the passkey window (PATH B, `discoverKey`). An unconfirmed create is confirmed by the next ask for the same name only when it is a create, never by a discovery.
- **Where the prompts run.** Import, restore, the account file and the unlock method run the passkey card in the page (PATH A); on Firefox's toolbar panel the phrase import, the account file and the unlock method move to their own window first (D15's pattern, `utils/own-window.ts`), as Full Backup and restore already did. Only create keeps PATH B, where the discovery step also runs.
- **UI.** The unlock choice is `components/composite/import/UnlockMethodChoice.vue` around `AuthMethodTabs` (D18), shared by both import forms. The reuse link is `components/composite/PasskeyReuseLink.vue`, under the create or import button on Create, Import and Restore; on the popup it takes the prototype's tighter spacing and secondary ink. The account file's passkey path is select, agreement, "Confirm with passkey", the file password, "Save account file"; the answer is held for the profile, network and account it was given for, and any reset drops it. The Lock page's strict-mode description and confirm text are P86-10's for every profile. One type-role exception: the selected unlock tab takes segment's active weight (`scripts/type-roles/exceptions.ts`).
- **E2E.** The phrase and backup forms open on Passkey, so the password drivers pick the Password tab first. `passkey-backup` restores under a passkey; `toolbar-panel`'s passkey backup restores under a passkey in its window.
