## Aztec V6

- **Fetch the default token list instead of building it in**, so that adding a token needs no release. Seeding runs with zero interaction, which is why the list and its pins ship in the build (`apps/extension/src/wallet/services/token/default-tokens.ts`). The fetch must reveal no more about the user than the price fetch does: one request, the same for every install, never keyed to a profile, an account or a holding. `apps/extension/store/remote-code.md` and both stores' declarations must cover it. ## Grants and scopes

- **Every other failure before a dApp send is claimed reads "Popup closed early".** `failQueuedForError` files anything but a scope refusal as `popup_bound` (`apps/extension/src/wallet/services/wallet-sdk/queued-journal.ts:244`, from `background.ts:1228`), and so does the ended-session path (`background.ts:1183`): a Terms refusal, a missing capability, a malformed request. Their honest labels are a copy decision, and the Terms case is next in line. From [dapp-grants](archive/dapp-grants/plan.md).
- **A dApp cannot widen a contract-classes grant.** Coverage is type-only (`packages/wallet-bridge/src/dispatcher.ts:719-720`), so a wider request opens no window unless the type was rejected before (`:514`). The answer shows the held classes, truthfully, but the dApp has no way to ask for more; a field-aware coverage rule is a product change for its own plan. From [dapp-grants](archive/dapp-grants/plan.md).
- **Repeated scope refusals pile up in Activity.** Every scope-refused send leaves one failed row, which the GC never evicts (`apps/extension/src/wallet/services/operation-journal/gc.ts:17-24`, `:127-130`), and the per-session cap of 8 counts only `queued` rows (`apps/extension/src/wallet/services/wallet-sdk/queued-journal.ts:37`, `:176-187`), so a connected app that retries a refused send adds one card per try, with no limit. Cap or merge repeated refusals per session. From [dapp-grants](archive/dapp-grants/plan.md).

## Wallet safety

- **The address-keyed fee maps outlive a deleted profile off the live path.** `nulo:ui:feePaymentMethods` and `nulo:ui:sendFeePaymentMethods` hold `{ [address]: … }` (`apps/extension/src/popup/components/modules/send/FeeSettingsCard.vue:335-338`, and `withSendSlot` in `fee-send-selection.ts` beside it). Pruning by address is unsafe, since two profiles can share one, and moving the global wipe onto the other paths changes their behaviour: it needs its own decision. From [wallet-safety-fixes](archive/wallet-safety-fixes/plan.md).
- **An Allow the watchdog displaced mid-un-hide leaves receipts hidden under `trusted`.** After a stall of five minutes or more inside the lock, a displaced Allow with no Block after it stops un-hiding, and only `setTrustAllow` writes `hidden: false` (`unhideLocked`, `apps/extension/src/wallet/services/incoming-transfer/service.ts:658-674`), so nothing un-hides the rest. It is an accepted residual; a `(BUG PIN)` in `service.scenarios.test.ts` holds it. Candidates: re-run the un-hide on replay, or un-hide before the trust write, which needs a `pending` trust row first because the floor skips a contract with none (`:866`). From [wallet-safety-fixes](archive/wallet-safety-fixes/plan.md).
- **A pin or a token-deletion cleanup racing a profile deletion can recreate its pinned-tokens key**, an accepted residual. The purge removes `nulo:ui:pinnedTokens@<id>` on every deletion path, but a popup that has not yet seen the deletion can write it again (`pin` and `onTokenDeleted`, `apps/extension/src/composables/usePinnedTokens.ts:214-243`). A restore that reuses the id then shows those pins (`apps/extension/src/wallet/services/profile/service.ts:1526-1529` frees the id; `operation-journal/service.ts:273-274` says why ids come back); otherwise the key stays as an orphan. Fixes: fence the key by incarnation, or a sweep cheaper than reading the whole store at every background start. From [wallet-safety-fixes](archive/wallet-safety-fixes/plan.md).
- **Two of the token add's compensations delete by id without lock ownership.** `persistToken`'s post-set deletion and network checks (`apps/extension/src/wallet/services/token/service.ts:419-431`) delete `token.id` even when the lock's watchdog displaced the add, so a same-id restore's row can go with it; the last check before `onTokenAdded` deletes only while the add owns the lock. At those two points the row may postdate the purge's snapshot, so skipping the delete can orphan it: the choice needs its own decision. From [wallet-safety-fixes](archive/wallet-safety-fixes/plan.md).
- **Recovery phrase and Change password have no submit latch.** A mouse double-click on Retrieve runs `handleUnlock` twice (`apps/extension/src/popup/pages/settings/security/export/seed.vue:55-67`), and the second `countdown.start()` leaves a 5-minute close that "keep open" cannot cancel (`apps/extension/src/composables/useSecretCountdown.ts:26-35`). - **Two keyboard focus rings do not show.** The sub-page back arrow is a bare `<button>` (`packages/design/src/ui/SubPageHeaderBase.vue:36-45`) under the base stylesheet's `button { outline: none; }` (`packages/design/src/base.css:270-275`), on every page built on `SubPageHeader` or `CollapsingHeroLayout`, and onboarding's active method tab draws its `:focus-visible` outline in `--nulo-accent` over a fill of the same colour (`apps/extension/src/onboarding/pages/create.vue:231-239`).
