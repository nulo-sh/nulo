# Phase 0: recon, spike and plan consults

## Spike

- A throwaway network spec (never committed) drove each dApp window through an unplanned restart (`stopBackground`) and the lock's planned restart (#907's `refuseSessionDeletes` + `pressHeaderLock`), recording the window and the playground at +1 to +35 s, plus a notice variant that sent `session-disconnected` per live session before `runtime.reload()`.
- Chrome run 1: 14/14 at retry 0. Run 2 (planned rows with URL, listing and screenshots, plus the `getContexts` listing): the listing passed; the two planned rows recorded their data and then timed out in `evaluateInBackground`, which attached to the dead worker's target after the reload (the harness's `backgroundOrigin` note on #907 describes the same Chrome behaviour).
- Firefox: 11/11 at retry 0.
- `evaluateInBackground` returns no promise result (no `awaitPromise` on Chrome; a JSON round trip of a sandbox eval on Firefox): an async probe stores its result on the page or worker global and a second call reads it. On Firefox a fresh sandbox per call means `globalThis` does not persist; `window` (the page, through the sandbox prototype) does.
- The same-page reconnect probe was confounded: after the restart the wallet is locked, so a connect queues behind the lock screen on both browsers.
- Spike 2 (Chrome, after audit round 1): the background fired `windows.remove` for the open request window (its id read before the lock) and `session-disconnected` per session, then `runtime.reload()`, with nothing awaited. 6/6 at retry 0 (check, capabilities and connect windows, two runs each): every window closed by +1 s, no New Tab window, and every app with a session read `disconnected`. The first attempt was started at load1 180 by mistake and stopped within seconds, before its build finished; the run that counts started at 148.

## Consults

- **Round 1, Codex (`gpt-6.1-sol`, high, session `01a15917…`): reject.** Blocking: (1) the lock routes a check window to `/popup/auth` before a `getContexts` read before the reload (verified: `app.vue:332`, `locked-state.ts`; the check window has no lock handler, `useDappApprovalWindow`'s other windows reject and close); (2) awaiting the preparation widens #907's interval with an undeletable record. Also: close tabs not windows; frame-0 send tracking; an idle app in the planned e2e; F1/F7 wording; OA-1 as open. Verdict: accepted 1, 2, 3, 5, 6, 7; 4 moot once nothing is awaited.
- **Round 1, Opus (Plan): conditional approve.** Same finding 1 (and that the planned e2e's capabilities window closes itself on lock, so it could not see the miss); line budgets of `bootRuntime` (74/80) and `initWalletSdkHandler` (76/80, 79 with #886); #886 shares `background.ts`, `chrome-browser-api.ts`, `window-port.ts`, fakes; the await as a known limit; call order and a synchronous throw; the Lock popup held during the wait; Firefox crash e2e Chrome-only; #924 narrowed not removed; ordinary-window removal.
- **Resolution.** The two audits disagreed on the await (Codex: owner must approve any widening; Opus: known limit). Spike 2 removed the question: fired, unawaited sends and removals land, so the plan awaits nothing. Window identity for the lock's restart moved from `getContexts` to a tracker at the background's `WindowPort` (creation and navigation URLs), which needs no change to `verify-admission.ts` or `WindowManager`'s log-only `kind`.
- **Round 2, Codex (resumed): conditional approve.** `new URL(...).origin` is `"null"` for `chrome-extension:` and `moz-extension:` (demonstrated under Bun), so the rule compares `protocol`, `host`, `pathname`; the tracker delegates through the original adapter and guards each removal; KL1 widened to the lock's restart; KL3 rewritten (a page cannot post before Ready, which follows the sweep); I2 narrowed. All accepted.
- **Final fresh Codex pass (new session): conditional approve, then `approve` on verification.** Conditions: Phase 3's network command needed `NULO_E2E_PROVERLESS=1` (`agent.sh`'s guard refuses a `@requires-proverless` file without it) and the smoke command `NULO_E2E_MIGRATION_FIXTURE=1 NULO_E2E_CSP_REPORT=1`; the file map needed `wallet-sdk/test-ports.ts` and `background.connect-window.test.ts`. Both applied.
