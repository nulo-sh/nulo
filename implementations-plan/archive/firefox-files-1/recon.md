## Verified claims and corrections

- **The Firefox panel's restore already moves.** `popup/pages/import.vue:151` moves every Full Backup restore (`option === "full_backup" && passkeyNeedsOwnWindow()`) whatever the backup's kind, because the kind is unknown until the file is read. The report's "only a passkey restore moves" does not hold for that page. The full-backup restore picker the panel still opens is `popup/pages/restore-again.vue` (`useRestoreAgain.ts:144`, from Home's `RestoreOutcomeBanner.vue:62`).
- **Production `pickFile` callers** (`grep "pickFile("` over `src`, tests excluded): contacts import (`useContactImportExport.ts:156`), account-file import (`settings/accounts/import.vue:65`), the profile restore (`useProfileImportFlow.ts:231` → `useFullBackupImport.ts:543`, moves already), restore-again (`useRestoreAgain.ts:144`), onboarding import (a tab, not exposed). Each call starts in the press's turn; the contacts import passes `delay`, so its input is clicked 50 ms later (`files.ts`).
- **A window on an unlisted route.** `captureOwnWindow` ignores it; an unlocked session renders the route, a locked one lands Home after the unlock (`postAuthRoute`), and its back arrow walks history. The report's "boots to Home" holds only through the lock screen.
- **The export's wait.** `getSendersAcrossActiveNetworks` (`account-state/service.ts:93`) checks each chain-unique network in turn with `getNodeStatus`. The report's timings follow: an unreachable node costs the backoff (about 6 s), a silent one the 60 s request limit.
- **A cold PXE also calls the node.** `getSenders` → `viaPxe` → `packages/aztec-runtime/src/pxe/service.ts:400` → `withPxeRead` → `registry.ensure` on a chain with no runtime yet → `createChainRuntime` (`chain-runtime.ts:171`): the retrying node client, `getL1ContractAddresses`, `createPXE`. A network that answers the probe and is not yet bound (not the active one, or the first read after a restart) still builds its PXE inside the export. The probe bounds the check, not that build.
- **PR #944 does not touch `own-window.ts`.** Its diff adds `wallet/services/window-manager/restart-ended-windows.ts`, which matches only `#/windows/{discover,capabilities,verify}` URLs. Own windows are `#/popup/...?window=own`: no textual or semantic overlap.
- **The `account-state` backup has the same wait** (`service.ts:241`, `getNodeStatus` per network). Out of scope: the full backup shows its own working card, and bounding it would drop a slow network's contract state from a backup.
