# Phase 1: build H1 and pin it

- **A bare token registration renders no token row.** `seedTokenRow` alone left Home with no `tokens-card`: Home lists a token only with a stored balance row, and the balance service reads its token map only as it starts. The pin therefore rides the placeholder-row spec, which already writes a balance row and restarts the background.
- **Red/green.** With the base CSS and the new pins, Home's activity row stopped 16 px and Home's token row 24 px short of the left edge; with only the sticky bleed reverted, Holdings' search bar stopped 24 px short. All pins pass with the change, on Chrome and on Firefox 158.
- **`.pick` against `.link`.** `.link` uses logical `margin-inline` / `padding-inline` and `.pick` physical `margin` / `padding`; the later rule wins across the pair, as CSS Logical specifies. Measured live: a `.pick` row inside a host that sets `--page-gutter` computes margin −8 px and padding 8 px.
- **Codex consult** (`gpt-6.1-sol`, high, one pass over the plan and the diff): no demonstrated regression. Accepted R1 (pin the sticky bleed and the token page in existing scenarios), R2 (the fallback keeps the earlier geometry; it does not make a later host safe) and R3 (the rows' comments state the no-side-inset constraint). Verified after the fixes: `rows.test.ts` green on Chrome and Firefox, the sticky pin red without its bleed.
