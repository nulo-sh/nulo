# Phase 1 (A1) · registry, read code, scan

- **Cycles.** The registry cannot be what services build from: it imports UI decoders (Vue) and service modules. So the stores the wallet constructs live in `wallet/storage/stores.ts` (spec-module imports only, no cycle, no UI code in the worker bundle); `stored-shapes.ts` builds its codec entries from that table and is read by tests and the generator only. Factories take a store name; the profile and the four plain value stores take their row type as the caller's claim, which the writer round trips hold.
- **Constants moved, not duplicated.** Inline roots (`nulo:core:dappSessions`, `nulo:journal`, the five `incoming-*`, prices, token list, seeder markers, active network) became exported constants in their spec modules; `PROFILE_STORAGE_ROOT` moved to `profile/spec.ts` and `CONFIG_STORAGE_KEY` to `config/config.ts`, their importers updated.
- **Decoders exported unchanged.** `decodeStoredConfig` (the per-prop merge `load()` adopts), `usableQuotes` / `isValidQuote` (now with `now`), `decodeTokenListState`, `decodeSeedMarkers`, `decodeActiveNetworkId`, `decodeRestoreOutcome`, `readSendPicks`. The services call them; the touched suites (codecs, profile repo, balances, incoming, price, token list, config, backup, dApp sessions, auth registry: 41 files, 993 tests) stay green unchanged.
- **Type check is mutual assignability**, not the strict `Equals` trick: the strict form reports an intersection (`Profile`) and its flattened schema output as different types even when every field agrees.
