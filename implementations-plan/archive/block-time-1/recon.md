## What the local network does on this line

- **The harness boots** `aztec start --local-network` with `SEQ_MIN_TX_PER_BLOCK=0`, its own per-run data dir and ports, and its own anvil with `--slots-in-an-epoch 1` and no `--block-time` (`apps/extension/tests/e2e/global-setup.ts:404-407, 530-577`). The lane brief's "nothing sets a sequencer min-tx value" does not hold: `SEQ_MIN_TX_PER_BLOCK=0` is set (`:555`), and is inert (below).
- **The CLI passes only** `l1Mnemonic`, `l1RpcUrls`, `testAccounts` to `createLocalNetwork` (`<aztec>/aztec/dest/cli/aztec_start_action.js:24-28`), which then forces `useAutomineSequencer: true`, `automineEnableProveEpoch: true`, `realProofs: false`, `aztecEpochDuration: 4`, `aztecProofSubmissionEpochs: 2`, committee size 0, slasher off (`<aztec>/aztec/dest/local-network/local-network.js:77-110, 46-56`). `AZTEC_EPOCH_DURATION` and `AZTEC_PROOF_SUBMISSION_EPOCHS` in the env are ignored.
- **The `aztec` wrapper** (`<aztec>/aztec/scripts/aztec.sh:40-60`) exports `ARCHIVER_POLLING_INTERVAL_MS`, `P2P_BLOCK_CHECK_INTERVAL_MS`, `WS_BLOCK_CHECK_INTERVAL_MS`, `ARCHIVER_VIEM_POLLING_INTERVAL_MS`, `SEQ_TX_POLLING_INTERVAL_MS` as 500 with no `:-` guard (a caller cannot change them by env), and starts a second anvil that fails its bind on the harness's port (`global-setup.ts:582` already says so).
- **The AutomineSequencer** (`<aztec>/sequencer-client/dest/sequencer/automine/automine_sequencer.js`) replaces slot-timed production. It polls the mempool every 50 ms (hard-coded, `:117`), builds one single-block checkpoint as soon as `minTxsPerBlock` (floored at 1, so `SEQ_MIN_TX_PER_BLOCK=0` changes nothing) age-eligible txs are pending (`:351`), pre-sets anvil's next block timestamp to the next L2 slot boundary (`:372-380`), publishes in place with `sendRequests` (never the slot-waiting `sendRequestsAt`, `:478-481`), forces an archiver sync, and moves the `TestDateProvider` to the new L1 time (`:496-499`). A settler tick every 200 ms (hard-coded, `:154`) marks the checkpointed tip proven with cheat codes and `evm_mine`s one L1 block. At start it sets anvil to automine with interval mining 0 (`:134-139`), which cancels any `--block-time`. It contains no sleep, timetable or slot wait (grep of `imetable|sleep|setTimeout|Date.now`: comments only).
- **Consequence (inferred from code, to be measured):** the L2 slot duration changes chain time, not wall-clock. Each build warps L1 time to the next slot boundary; each settle `evm_mine` adds `ETHEREUM_SLOT_DURATION` (deploy calls `anvil_setBlockTimestampInterval(ethereumSlotDuration)`, `<aztec>/ethereum/dest/deploy_aztec_l1_contracts.js:329-336`). Over a suite of hundreds of txs at 72 s slots, the chain clock runs hours ahead of the wall clock.
- **The wall-clock gates on the node path** (what does cost real time per tx): `P2P_MIN_TX_POOL_AGE_MS` = 2000 ms of the node's `TestDateProvider` time before a tx is build-eligible (`<aztec>/p2p/dest/config.js:341-345`, `tx_pool_v2_impl.js:783-785, 857`), env-settable at boot (not at runtime: the admin schema strips it, D12); that clock jumps at every build (to the slot boundary, forward at 72/12, backward at short slots when blocks are rarer than the slot) and at every settle (by `ETHEREUM_SLOT_DURATION`), so the real wait is not a constant (audits r1); the 50 ms mempool poll; the 200 ms settler; the RPC unseen-block hold-off, only for a read of a block the node has not seen (`RPC_UNSEEN_BLOCK_BY_NUMBER_WAIT_MS`, 2 × `blockDurationMs`; by hash 3 s; `<aztec>/aztec-node/dest/modules/unseen_block_hold_off.js:10`); the client side `waitForTx` (`initialDelay` 1 s then 1 s polls, `<aztec>/wallet-sdk/dest/base-wallet/base_wallet.js:394-409`, `<aztec>/aztec.js/dest/utils/node.js:35-71`).
- **Slot constraints:** `AZTEC_SLOT_DURATION` (default 72) and `ETHEREUM_SLOT_DURATION` (default 12) parse as integers (`parseSafeInteger`), must be positive, the L2 slot a multiple of the L1 slot (`<aztec>/ethereum/dest/config.js:12-21, 191-203`), and are fixed in the L1 rollup at deploy (`checkConfigMatchesRollup`, `<aztec>/aztec-node/dest/factory.js:553`). Both are honoured from the env by `--local-network`. A 500 ms slot cannot be expressed: `parseSafeInteger("0.5")` throws (`<aztec>/foundation/dest/config/index.js:223-228`), and EVM timestamps are whole seconds.
- **Tx receipt status** (`<aztec>/aztec-node/dest/modules/node_tx_receipt.js`): PROPOSED once the automine `addBlock` runs (before L1 publish), CHECKPOINTED after the post-publish sync, PROVEN after the next settler tick, FINALIZED when the L1 `finalized` block holds the proven checkpoint (the harness's `finalizeThrough` mines empty L1 blocks for it, `fixtures/aztec.ts:860-878`). Anvil's `finalized` offset is recalled, not verified.
- **`aztecDebug` namespace** is served on the node's main port (`registerAztecNodeRpcHandlers(..., {debug: true})`): `aztecDebug_mineBlock` (an empty block through the same serial queue), `aztecDebug_prove`, `aztecDebug_warpL2TimeAtLeastTo|By` (`<aztec>/stdlib/dest/interfaces/aztec-node-debug.js`). The comment in `fixtures/aztec.ts:472` ("the node-admin `mineBlock` is not RPC-exposed") does not hold on this line.
- **The PXE syncs on demand only** (`<aztec>/pxe/dest/block_synchronizer/block_synchronizer.js`, no timer; `syncChainTip` defaults to `proposed`). The wallet passes only `dataDirectory` and `proverEnabled` (`packages/aztec-runtime/src/pxe/chain-runtime.ts:180-185`). The browser copy of `@aztec-labs/pxe` differs from the installed one only by Nulo's `registerAccount` patch.
