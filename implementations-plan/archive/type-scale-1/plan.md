No box changes: if Phase 3 reads the Header's fixed 26 px `.lock_chip` apart from the `.network_chip` beside it (which grows with its 11 px line), that is an OA-1 entry with both heights.
- **Guard** (`type-role-ban.test.ts`): today `composedRole` (`:177`) and `elementCarrier` (`:377`) drop a `type--X` that names no role, and `namedRoles` (`:372`) drops any unknown literal of a bound `:variant`. Each becomes a hard "not a role" finding, as a static `variant` already is (`:405`). For a bound `:variant` only literals in result position count: the whole expression, or a branch of a conditional, found with the TypeScript parser the file already imports; a comparison operand (`kind === 'address' ? 'meta' : 'body'`) is not one.
- **Layout gate** (`fixtures/type-roles.ts`): the toolbar-panel test's clip predicate (`type-roles.test.ts:582-590`) sees only role-bearing elements and only boxes that do not show their overflow, so the role-less head words of `DetailsTable.vue:71-76` or `PublishStrip.vue` could run into each other unseen. A new `ReadScope` kind, `laid-out`, collects in the page, once, the union of role-bearing elements (native fields included) and visible elements with text of their own. One exported `overflowingText(readings)` replaces the panel predicate: a visible element clipped by an ancestor without an ellipsis, or whose `scrollWidth` exceeds its `clientWidth` by more than 1 px without an ellipsis, whatever its `overflow-x`. A native text field, and an element whose `overflow-x` is `auto` or `scroll`, scrolls its own content by design (Holdings search holds a pasted 66-character address, `type-roles.test.ts:243-246`), so for those only the ancestor-clip branch counts. `expectPageClean` (smoke), the windows spec's sweep (network), the panel test and the windows spec right after `stretchPayload` (`network/type-roles-windows.test.ts:232-237`, the hostile-length strings) read `laid-out` once per state and assert it; the added reads are measured in Phase 1. The probe test (`type-roles.test.ts:71`) gains two controls: an input whose box an ancestor clips is reported; an input scrolling a long value is not.

## Security & Adversarial Considerations

- **Threat model**: no new input, trust boundary, permission, storage or message; the change is CSS classes and test code. The security-relevant property is legibility on the approval windows, where a person compares names, addresses and hashes. An attacker who controls a dApp's call can choose long names and payload strings; the boundary is the person's reading of what they approve.
- **Newly cut text on an approval window is an owner ask, never a silent ship.** Predicted instance (arithmetic, not yet rendered): the identity strip caps the network name at 96 px (`IdentityStrip.vue:86-94`); "Local Network" is about 86 px at 11 px and about 101 px at 13 px (JetBrains Mono advances 0.6 em), so `meta` at 13 would cut it. Phase 3 shoots the windows with long account and network names and an account-picker row (`AccountSelectRow.vue:187-195`); every new cut goes to OA-1 with its screenshot.
- **Identifiers stay in mono roles above `MIN_MONO_PX`**; the identifier rule and the hex scan still refuse an identifier outside one. The wire-shaped fixtures (`OperationCard.long-strings.test.ts`, `payloadPastCard` in the windows spec) keep proving a long payload stays inside its card.
- **Supply chain, crypto, least privilege**: none touched; no dependency, workflow or lockfile change.
