## OA-1 (#1232): a notice whose text holds one string wider than the card

- **Surface**: the notice card (`apps/extension/src/components/NotificationManager.vue`), shared by the popup and the onboarding tab. Today one notice can carry such a string: onboarding's "Import completed with errors", after View Errors, which names the networks that did not finish restoring. A network name typed in the wallet is at most 25 characters; a backup file can carry any length.
- **Today** (`1232-today-popup`, `1232-today-onboarding`), with a 90-character name from a hand-edited backup, `aztec_devnet_eu_west_1_staging_node_for_internal_load_testing_with_the_real_prover_enabled`:
  - Popup: the name is one line wider than the popup; both of its ends are cut off at the popup's edges and cannot be read.
  - Onboarding: the name runs about 27 px past each side of the card, over the dimmed page. The card holds names up to about 80 characters; the popup's about 50.
- **(a)** (`1232-a-popup`, `1232-a-onboarding`): the card breaks a string wider than itself where it must. The rule is `overflow-wrap: anywhere` on the card. The name stays whole and readable inside the card, split across lines at the card's edge (in the popup: `…_for_inter` / `nal_load_…`). Ordinary text still breaks at spaces: the "Profile creation failed" notices render unchanged (measured, with and without their note, same lines and height at five widths), and a restore notice changes only when its text runs past the card's padding today, as in the pictures. It covers this notice only: the same name also shows in the import warning on the page behind it, the failed-Retry line, Home's reminder and Restore again's intro, which may run past their boxes the same way (not measured; filed as a separate issue).
- **(b)** (`1232-b-popup`, `1232-b-onboarding`): the restore texts shorten a network name longer than 25 characters (the most the name field accepts) to its first 24 characters and an ellipsis. The notice reads "Some entries from the backup couldn't be restored. aztec_devnet_eu_west_1_s… didn't finish restoring." The same cut applies to every restore text that names networks: the import warning, Home's reminder, Retry's result line, Restore again's texts and its toast, so it also bounds those places for ordinary letters. It does not bound the width: 25 very wide characters, which a backup can carry, still overflow.
- **(c)**: leave it as it is.
- **Recommendation**: (a). It fixes the card, where the defect is, for every notice and both shells with one rule, and changes only text that overflows today. (b) changes copy in seven texts, hides part of the name the person needs to tell which network failed (two names that share their first 24 characters read the same), and keeps the card's flaw for any other text. (c) leaves the popup showing a name nobody can read.
- **One cost of (a), shared with today**: the card does not scroll. Text tall enough to pass the bottom of the window pushes OK below the fold for a pointer; Enter and Escape still close it, since the keyboard starts on OK. Today about 90 network names do this. With (a), one very long name can too: in the onboarding tab at 800 px a 1,500-character name still leaves OK in view, but a shorter window or a longer name does not. Both need a crafted backup. The lane records it as a known limit rather than change the notice's layout.
