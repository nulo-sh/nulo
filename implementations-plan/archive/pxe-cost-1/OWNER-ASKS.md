# pxe-cost-1: owner asks

The plan is [plan.md](plan.md). One ask, OA-1, for #1034. No arc of this plan waits for it: A1 (#1038) changes nothing a person sees, and nothing of #1034 ships until OA-1 is answered. The answer becomes its own plan or lane.

## OA-1: which contacts the wallet registers as senders (#1034)

- **Why it is open.** Each sender the wallet registers makes the wallet scan more after every new block: 84 × (watched tokens + 1) more tags a block for each account, until the sender is removed (168 with one watched token and one account). In pxe-limits-1 (#1016) the first wallet action after a block took 0.83 s with no senders, 5.1 s with 32 and 15.1 s with 128 (Chrome, one watched token, one account, a busy shared host); Firefox took 8.7 s at 128. While that scan runs, sends and dApp requests wait. Today a contacts-file import registers every row the file marks as a sender, with no total; the file allows 512 rows.
- **What a sender is for.** Most transfers reach the wallet without any registration: the default way Aztec wallets tag a private note (a "handshake") lets the recipient find it alone, and Nulo's own sends use it. A registered sender matters only for a sender whose wallet tags notes with an address-derived secret. Without the registration those notes never appear; the person can still add the sender later on Settings → Developer → Account State → Senders, and the notes then appear.
- **Cost per block of each option, by how many contacts an imported file flags.** One watched token, one account, no handshakes, no other senders. Tags are exact (the measured formula); times at 0, 32 and 128 senders are measured, other times follow the measured slope of 0.11-0.13 s a sender on that host. With the four default Testnet tokens every tag count is 2.5 times these (predicted, not run).

| Option | 32 flagged contacts | 128 flagged contacts | What a person notices |
|---|---|---|---|
| **A. Keep today's (ships now)** | 5,546 tags, 5.1 s | 21,674 tags, 15.1 s | Nothing changes. |
| **B. Import registers none** | 170 tags, 0.8 s | 170 tags, 0.8 s | The import screen no longer says "N senders will be registered on …", and its toast no longer counts senders. Senders an earlier import registered stay until removed on the Senders page. A sender comes only from the Senders page, a dApp, or a full-backup restore. |
| **C. Register a contact the first time the person sends to it** | 168 × (contacts sent to + 1) + 2 tags; 5 of them: 1,010 tags, about 1.4-1.5 s | same, by contacts sent to | As B on the import screen. A note an address-derived sender sends before the person's first send to them is not found until then. The first send to each contact also makes the PXE re-sync every token once (registering a sender resets its contract sync cache), so that send starts slower. |
| **D. A cap (for example 16 senders per network), the oldest dropped** | at most 2,858 tags, about 2.6-2.9 s | same | As today until the cap; then the oldest sender stops being looked for, with no message. The wallet must keep a new saved list of senders with when each was added, order the senders that exist today, and apply the cap on every path (import, dApps, restore, the Senders page). |
| **E. A switch on each contact ("look for transfers from this contact")** | 168 × (switches on + 1) + 2 tags | same, by switches on | A new switch on the contact screen, off by default, with its explanation; the screen could show its cost. Import sets nothing. This reverses the earlier decision that contacts never touch senders (the `contacts-sender-decouple` plan). |
| **F. A total (for example 16 senders per network) across every path, refused past it** | at most 2,858 tags, about 2.6-2.9 s | same | An import past the total registers the first rows up to it and says how many it skipped; a dApp's registration, a restore and an add on the Senders page past it are refused, each with its own message. Senders already past the total stay until removed. No saved list: the wallet counts the PXE's own senders, and the count and the registration must run under one lock on every path, or two registrations at once pass the total. |

- **Not in these options.** dApps may still register up to 128 senders per network, and a backup restore up to 64; only D and F would count them. Own accounts and watched tokens also multiply the cost; they are measured, not changed.
- **Recommendation: B.** It prevents the cost of future imports (senders an earlier import registered stay until removed), adds no saved state and no new screen, and loses only notes from address-derived senders, which the person can still add by hand. F is the next best if you want a hard ceiling on every path; it changes the import's message, refuses some dApp calls, restores and manual adds, and needs one lock around counting and registering. C hides a cost in the first send; D adds a saved list and drops senders silently; E adds a screen and reverses a decision.
- **What ships now:** A. Nothing changes until you pick; #1034 stays open with this ask.
