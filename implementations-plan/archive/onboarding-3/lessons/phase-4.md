# Phase 4: Home's Get started card and the backup banner

- First whole-smoke run on Chrome (retry 0, 2130 s): 56 files passed, 1 failed, `rows.test.ts` "Home's hero stays fixed over a scrolling middle". The card waits for its reads (OA-4), so it mounted after the rows had settled and while the spec held the middle at 200 px. Scroll anchoring moved `scrollTop` to 472 and `maxScroll` from 333 to 609. Fix: Home's scroller carries `data-reminders-settled` (the `tokens-list` `data-settled` precedent), and `waitForHomeReminders` (`tests/e2e/fixtures/tokens.ts`) gates the spec before it measures. The Firefox half of that run was stopped before it started: the fix needed a full rerun on both browsers anyway.
- `storageLocalSet` awaits `migrationIdle()`, a storage round-trip, before it writes. A flag written with `void` before `window.open` can therefore die with the toolbar popup when the new tab takes focus. The How Aztec works row awaits the mark, then opens the tab, as the plan says. A unit test pins the order (a mutation to `void` fails it), and `security-backup` proves a real browser still opens the tab after the await.
- The smoke egress guard fails a launch on any undeclared outside host. Clicking a real external link in smoke means declaring its host in `DECLARED_REFUSALS` with the reason (`tests/e2e/fixtures/egress-guard.ts`).
- `frozen-account-canary` reveals the phrase before it mints, so it can never show the funded banner. The funded-banner e2e lives in `hero-prices-unavailable`, whose wallet arrives funded from a backup (D13).
- Second whole-smoke run: Chrome green (57 passed, 6 skipped, 1996 s). Firefox (2761 s): 59 passed, 1 failed, the How Aztec works step in `security-backup`. The tab opened and the flag was stored, but the row stayed. Instrumented, the page's `storage.onChanged` listener fired and re-read, and that re-read, issued from the listener in the page that wrote the flag, still answered `aztecOpened: false`; a later `get(null)` answered `true`. Chrome never showed it. Fix (`fix(home): get started flags take a change event's own values`): the listener applies the event's `newValue` (`changedGetStarted`), and a read that lands after an event keeps what the event said. Unit-pinned with storage that still answers the old value. Precedent check: `usePinnedTokens` also re-reads from its listener, but for writes from another context; not reproduced, not changed.
