## Facts the plan rests on

- **The fee path raises the same assertion text an app does.** The PrivateFPC artifact (`@alejoamiras/private-fee-juice` 6.0.0, `target/private_contract-PrivateFPC.json`) declares the error strings "Balance too low" and "Amount too low to cover gas cost"; Token's transfer raises "Balance too low" too (the prototype's frame `p110-1619-a`). A popup that reads only the message cannot tell which contract failed.
- **A popup send at `submitting` can stay in flight across a lock and an unlock** (the third explorer, narrowed by the Opus audit). The lock's sweep (`execution-lane.ts:255-266`) cancels `queued`, `pending`, `simulating`, `proving` only and runs unawaited; auto-lock waits while approved sends run (`execution/service.ts:337`, `session-manager.ts:951-957`); a send at `submitting` during `node.sendTx` ends `succeeded` after the lock; a worker restart while locked leaves sealed records unreaped until `reapUnlocked` runs after the next unlock (`reaper.ts:171-179`), and no live send survives a restart. Journal ids are 64-bit random, re-rolled against live keys.
- **Today's no-from public call** (`tests/e2e/network/tx-sendTx-noFrom.test.ts:62-86`): approved, refused at build, the dApp gets `UNCLASSIFIED_ERROR_MESSAGE`, one `dapp_execute` record `failed` (Activity "Transaction failed / Reported by app").
- **`snack-placement.test.ts:502`** forces the execute window's estimate failure with an unfunded public transfer of 1,000,000 base units of TST (`:434-443`). Whether that failure reaches the popup as an assertion with Token in its call stack is not measured (Phase 1 measures it).
