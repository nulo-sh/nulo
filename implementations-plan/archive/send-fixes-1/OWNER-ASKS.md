## OA-1. #112: the lane brief against your page-15 pick

**Surface:** Home's and History's row, and the transaction page, for a send the node answered with an error.

**What happened:** the lane brief asks that "a refusal the node returns at send is a failed send at once, with the node's reason where the wallet can read one". On decision page 15 (OA-6) you picked **A**: "As is … nothing is built for #112, which stays open." Its reason still holds today: Nulo's default Testnet endpoint is dRPC's load balancer, which can pass a send to one node, give up waiting, and ask another node, which then refuses it. A row that read "won't go through" could be wrong, and a person who sends again would pay twice.

**Options:**
- **A. As is** (your pick on page 15). "Not confirmed yet", then "Unconfirmed" after 30 minutes, then "Won't go through" once the send's expiry is provably past.
- **B. Show the node's answer, keep the state.** The row keeps "Not confirmed yet"; the transaction page adds the node's reason, e.g. "The node answered: Invalid tx: Insufficient fee payer balance". New copy; the text comes from the node, so it needs a length cap and a rule against links.
- **C. Fail at once** (the brief's wording). The row ends as failed at once, accepting that through the load balancer it can be wrong.

**Recommendation:** A. B is the only form of the brief that cannot invite a double payment; pick it if the reason matters to you.
