# Phase 4: #268, reads that survive a restart

- `useConfigRead(config, fetch, land)` (`apps/extension/src/composables/useConfigRead.ts`): subscribes `onUpdate` and `onConnected` when called; the first open is the mount's, every later one calls `read()`; `read()` takes a `createRunFence()` run, starts a fresh set of keys updated since, awaits `fetch()` inside the `try` (a synchronous throw ends the read too) and lands only while current; `dispose()` invalidates the fence and removes both handlers. No `disposed` flag: after `dispose` nothing can call `read()` but the page itself, and no page does.
- Hub and Lock lost their own generation counter, fence set and connection counter; their `land` bodies are the old loops with `fence.has` → `updatedSince`. Lock's two `getValue` reads became `fetchLockConfig`. Display, Privacy and Developer read through the composable in their existing mount hooks (`onMounted`, `onMounted`, `onBeforeMount`); each `land` copies the values (Display keeps the dust threshold branch) and never calls `applySetting`.
