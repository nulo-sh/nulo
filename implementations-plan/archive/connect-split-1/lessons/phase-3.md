# connect-split-1, phase 3 (and the implementation review) — lessons

- The connect journeys first shared the file-scoped `localNetworkExtension`: the second journey's Connect then met the first's saved row and was answered as a reconnection, so no connect window opened and `waitForPopup(ctx, "discover")` timed out at 30 s. A journey that needs a first connection takes a wallet of its own (`registeredExtensionPerTest`, then `switchToLocalNetwork`).
- The playground's `pg-status` reads `connected` once keys are exchanged, before the emoji check is answered; "no key answered the check" is proved by the check page still open on its grid (either answer closes it), not by the dApp's status.
- A MutationObserver installed the moment `waitForPopup` resolves can meet a popup whose `document.body` is still null; observe `document.documentElement`.
- The extension page CSP refuses `page.addStyleTag` (`style-src-elem` violation, and the run fails on the CSP record). To stop a theme flip's transitions before a quick shot, `document.getAnimations()` and `finish()` each; a looping animation throws and is left alone.
- `shotSend` (two shots with a theme flip and settles in between) is too slow for the connect window after Allow, which lives about `BRIDGE_MS`; a dedicated two-shot helper with no settle fits.
- Capture mode only (`NULO_E2E_SHOT_DIR` set): `connect-verify-mismatch`'s reconnect case hung in `shotSend`'s second (dark) shot of the wallet tab and timed out at 150 s, twice on Chrome; without the shot dir both cases pass (head, Chrome, exit 0). CI never sets the dir. It predates this arc: the base (f214e5cb) with shots hangs at the same dark shot (the light one written, then 165 s of silence), and also times out reading the CSP record.
- Measured on Chrome under load ~170: a dApp that connects at once has its check window created 63–106 ms after Allow and the connect window removed 143–171 ms after; the grid was in the DOM by ~0.6–0.8 s (when the test first saw it, not a paint time). Firefox: +257 ms and +315 ms, grid by ~0.96 s. A dApp that starts its check 10 s late: connect window removed +1547 ms (Firefox +1606), check created +10045 ms (+10185). Smoke at retry 0: Chrome 267 passed; Firefox 266 passed and #849's flake.
- Implementation review: the per-tab cap counted unstarted reservations, which blocked a wallet picker's saved-row reconnection behind an Allow the page never used (Opus). Removed after a Codex consult (D8). Bridge holds keyed by request id let a stale establishment close a successor's window when a page reused the id (Codex); holds are now identity tokens, mutation-checked.
- `bun run test:e2e` builds nothing: it loads whatever `dist/<browser>` holds, and `e2e:agent` leaves a network build there (RPC pointed at the local sandbox). A smoke run after a network run therefore fails `import-dead-rpc` (its interception sees no RPC) and the backup-migration fixture contract. Build first as CI's source lane does (`VITE_NULO_E2E_MIGRATION_FIXTURE=1 VITE_NULO_E2E_TOKEN_SEEDS=1 VITE_NULO_E2E_TOKEN_SEEDS_CONFIRM=1 VITE_NULO_E2E_CSP_REPORT=1 bun run --cwd apps/extension build:<browser>`), then run with `NULO_E2E_MIGRATION_FIXTURE=1 NULO_E2E_CSP_REPORT=1`.
- Review rounds 1 to 3 left out the standard's two verbatim rules (smallest change; comments by value per character). A resumed Codex pass applied them to the whole arc: `conditional approve`, no behavioral finding, comment corrections only. Corrected were claims the code cannot hold (that no frame painted between the windows; a grid time "polled" when a MutationObserver records it), restatements and stale "every call" wording. Paste both rules into every review prompt, first and resumed.
- Firefox smoke at retry 0 under load1 ~110-200: one red, #849's open flake (`viewers-csp`, the selected line moved 72 px), in a file this arc does not touch; the occurrence is on #849.
- PR #886 opened as a draft while it conflicted with `dev` (two plans' lines at the end of `index.md`): GitHub created no merge ref, so no `pull_request` workflow ran and `gh pr checks` listed only CodeQL. Merging `dev` started every lane.
- Owner rework (2026-10-20). Settings' row link (`RowTarget`, testid `connected-app-row`) is a sibling of the row's text, not its parent, so a descendant selector from it finds nothing; and a testid shared by the list row and the app's page let `openConnectedApp`'s ready wait return while the list was still shown, so the page read hit the row. One testid per surface.
- A spec edited while `e2e:agent` is still setting up runs against the bundle built before the edit: a copy revert failed the next run on the old string. Every edit, copy included, needs a fresh run.
- The first review prompt quoted a draft of the row's words that the orchestrator's recorded call had already replaced, and Codex flagged the shipped words as wrong. Quote copy from the record (the issue comment), not from a working note.
- Measured after the rework (retry 0, load1 ~150 to 220): a dApp that connects at once has its connect window removed +19 to +36 ms after Allow and its check created +75 to +132 ms on Chrome, the grid in the DOM by 0.6 s (1.7 s at load ~220); Firefox +10 ms, +186 ms, 0.8 s. With the playground stalled 10 s: removed +15 to +18 ms, the check created +9.8 s (Chrome) and +10.3 s (Firefox); the Settings reads, both themes' pictures included, took 1.6 s and 2.1 s of the stall.
