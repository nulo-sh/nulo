# Phase 4: pinned Aztec toolchain install

- **Foundry attests its binaries, not its tarball.** `gh attestation verify foundry_v1.4.1_linux_amd64.tar.gz --repo foundry-rs/foundry` answers 404: the release's SLSA statement names the four extracted binaries (signer `release.yml@refs/tags/v1.4.1`, commit `cf774604…`, a self-hosted runner). The pin stays on the tarball (it equals the asset's GitHub digest); the binaries it holds were each verified against the attestation once, and the pin file's header records it.
- **The tarball's members are bare names** (`forge`, not `./forge`), unlike noir's (`./nargo`).
- **`--ignore-scripts` breaks the node without bcrypto.** With an empty rebuild list, `import('@aztec-labs/aztec-node')` and `import('@aztec-labs/aztec')` throw `Cannot find module 'bcrypto.node'` (bcrypto 5.5.2, via `@aztec-labs/p2p` → `@nethermindeth/discv5`, which selects bcrypto's native backend unconditionally). bcrypto's script is `node-gyp rebuild` over its bundled C, and its gyp file runs three local compiler probes (`deps/checks/*.sh`). It is the only package admitted; leveldown, lmdb, msgpackr-extract, `@parcel/watcher` and unrs-resolver load prebuilds, and protobufjs's script is a version check. The discovery spec passed with bcrypto alone.
- **`nodedir` is what stops the header download.** Control run without it: node-gyp wrote `~/.cache/node-gyp` (a download from nodejs.org). With `npm_config_nodedir` set to the running Node's prefix, nothing. npm 11.19 warns "Unknown env config nodedir" (the same for `--nodedir`); node-gyp reads the env var itself, so the env form survives npm dropping the pass-through.
- **The installer's `retry`/`dump_fail` turn errexit off** around the subshell that runs each step, so an override without its own `set -euo pipefail` would report a failed `npm ci` as success. Both overrides set it, as upstream's bodies do.
- **npm 11.19 has `allowScripts`** (a package.json allowlist with `--strict-allow-scripts`). Not used: CI's npm comes with whatever Node 24 setup-node resolves, and `--ignore-scripts` plus `npm rebuild <pkg>` works on every npm that runs `npm ci`.
- **Proof the e2e ran on the scratch install.** The host also has a `6.0.0-rc.1` toolchain under `~/.aztec`, so a green spec alone proves nothing; a second run's `ps` showed `.../arc2/home/.aztec/versions/6.0.0-rc.1/bin/aztec-anvil` (global-setup picks `$AZTEC_HOME/versions/<pin>` when all four tools are executable there).
- **A stray `apps/landing/src/generated/release.json`** (generated by the landing build before #49 removed that generator and its `.gitignore` line) sat untracked in the worktree; deleted, never committed.
