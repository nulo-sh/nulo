## Claims checked against the tree

- **#280** holds. `TxStatus` is `dropped | pending | proposed | checkpointed | proven | finalized` and `TxExecutionResult` is `success | reverted` (`@aztec-labs/stdlib/dest/tx/tx_receipt.d.ts`, 6.0.0-rc.1). The helper's branches for `success`, `app_logic_reverted`, `teardown_reverted` and `reverted` can never match a status. Measured: a public-reverted tx reaches `proven` with `executionResult: "reverted"` and the helper resolves on it. **Narrower count**: 17 call sites in 10 files at 29d9e49, not 20 in 13 (the issue counted the unmerged e2e-harness-gaps arc 3 branch). Receipt-only callers, the ones the bug can fool: `authwit-consume-smoke:85`, `execute-scope-chain:79`, `execute-scope-account:118`, `passkey-execution-canary:149,168,258`, `frozen-account-canary:291`, `snack-placement:225`, `selfpay-phase:227,385,452`.
- **#284** holds, lines exact (`owned-processes.test.ts:52-60` and `:90-93`, `owned-processes.ts:71-79`, `sandbox-ownership.ts:131`). **Wider than filed**: `ownerLives` (Firefox launch reaping) has the same blind spot.
- **#281** holds: `isBrowsingContextCompatible` (`BrowsingContextUtils.sys.mjs:239-244`, Firefox 153.0.4) skips extension contexts; on Firefox `ctx.pageErrors` and `ctx.consoleErrors` stay `[]` for a throw, a rejection and a native `console.error` (measured). **One claim narrower**: the issue's candidate "a privileged `nsIConsoleListener` registered through `chromeScript` ... attributed to the page's own window" cannot attribute in the parent process: the parent's copy of every extension-page error carries `innerWindowID` 0. Registered inside the extension process it attributes exactly. An "Unchecked lastError" message carries window id 0 in both processes, so no candidate can attribute it to a page.

## Conventions to match

- A browser difference lives on `BrowserDriver` or inside a driver's own launch, never in a fixture (FIREFOX.md § The one rule, enforced by `scripts/e2e/browser-seam.test.ts`).
- Privileged Firefox code is a string run through `WebDriverSession.chromeScript` (one exclusive call; it switches the session's context and focuses the first browser window, so it is never polled during a spec).
- Ownership and data dirs: launch records under `E2E_DATA_ROOT/webdriver-owned/<marker>.json`, removed by `releaseLaunch` on both the self and the orphan path.
- Driver unit tests sit in `ext/scripts/e2e/*.test.ts` and run in `bun run test`; Linux-only cases use `describe.skipIf(process.platform !== "linux")`.
- Network tests read `inject("aztecTestConfig")`; the script wallet is `createTestWallet` + `createSponsoredFeeOptions` with `E2E_FEE_GAS`.
